---
title: Недопустимые комбинаторы
icon: lucide/newspaper
---

> Исторически Sass был очень либерален в отношении использования ведущих, завершающих и повторяющихся комбинаторов в селекторах. Эти комбинаторы объявляются устаревшими, за исключением случаев, когда они полезны для вложенности.

Исторически Sass поддерживал три недопустимых использования комбинаторов:

* Ведущие комбинаторы, как в `+ .error {color: red}`.
* Завершающие комбинаторы, как в `.error + {color: red}`.
* Повторяющиеся комбинаторы, как в `div > > .error {color: red}`.

Ни один из них не является допустимым CSS, и все они заставят браузеры игнорировать соответствующее правило стиля. Их поддержка добавила значительное количество сложности в реализацию Sass и сделала особенно трудным исправление различных ошибок, связанных с правилом `@extend`. Поэтому мы [приняли решение](https://github.com/sass/sass/issues/3340) удалить поддержку этих использований.

**Есть одно важное исключение**: ведущие и завершающие комбинаторы по-прежнему могут использоваться для целей вложенности. Например, следующее по-прежнему полностью поддерживается:

<div class="grid" markdown>

=== "SCSS"

    ```scss
    .sidebar > {
      .error {
        color: red;
      }
    }
    ```

=== "SASS"

    ```sass
    .sidebar >
      .error
        color: red
    ```

```css title="CSS"
.sidebar > .error {
  color: red;
}
```

</div>

Sass выдаст ошибку только в том случае, если селектор всё ещё имеет ведущий или завершающий комбинатор _после разрешения вложенности_. С другой стороны, повторяющиеся комбинаторы всегда будут ошибками.

Чтобы убедиться, что существующие таблицы стилей, которые (вероятно, случайно) содержат недопустимые комбинаторы, мы поддержим переходный период до следующего основного выпуска Dart Sass.

## Переходный период {#transition-period}

Сначала мы будем выдавать предупреждения об устаревании для всех двойных комбинаторов, а также для ведущих или завершающих комбинаторов, которые оказываются в селекторах после разрешения вложенности.

!!! tip "Совет"

    Помните, что вы можете отключить предупреждения об устаревании из библиотек, которые вы не контролируете! Если вы используете интерфейс командной строки, вы можете передать [флаг `--quiet-deps`](../cli/dart-sass/#quiet-deps), а если вы используете JavaScript API, вы можете установить [опцию `quietDeps`](https://sass-lang.com/documentation/js-api/interfaces/StringOptions#quietDeps) в `true`.

Кроме того, мы сразу начнем опускать селекторы, которые, как мы знаем, являются недопустимым CSS, из скомпилированного CSS, с одним исключением: мы _не будем_ опускать селекторы, которые начинаются с ведущего комбинатора, поскольку они могут использоваться из вложенного правила `@import` или миксина `meta.load-css()`. Однако мы не поощряем этот паттерн и прекратим его поддержку в Dart Sass 2.0.0.
