> CSS добавил функцию `type()` с уникальным синтаксисом. Чтобы поддерживать гибкий синтаксис для этой функции, пользовательские функции с именем `type()` больше не разрешены.

CSS Values and Units 5 определяет [функцию `type()`](https://developer.mozilla.org/en-US/docs/Web/CSS/attr#attr-type) для использования в функции `attr()`. Эта функция определяет синтаксис, который следует использовать при разборе HTML-атрибута как значения CSS, поэтому, например, `attr(data-count type(<number>))` вернет значение атрибута `data-count` как CSS-число. Хотя в настоящее время она определена только в рабочем черновике, Chrome уже поддерживает функцию `type()`, поэтому Sass также добавляет поддержку.

## Устаревание {#deprecation}

Поскольку функция `type()` не следует обычным соглашениям для синтаксиса CSS-выражений, Sass будет необходимо разбирать её как [специальную функцию](../syntax/special-functions/), подобно `url()` или `element()`. Поскольку это представляет собой критическое изменение для любого существующего кода Sass, который определял функции с именем `type()`, Sass 1.86.0 объявил устаревшей возможность определять функции с этим именем.

## Критическое изменение {#breaking-change}

Современные версии Sass поддерживают функцию `type()` как [специальную функцию](../syntax/special-functions/), что означает, что она разбирается как тип строки без кавычек, который допускает необычный синтаксис вроде `type(<custom-ident>)`. Правилам `@function` в Sass больше не разрешено определять функции с именем `type`.
